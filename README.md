# skills — скиллы для агентов

Эталонные копии. `wk init` раскладывает их в проект; версионируются вместе с проектом.
Доставка и Go-валидация реализованы в `wk` по A3 из `../fix.md`.

## Почему одна папка, а не claude/ и codex/

Формат скиллов у обоих харнессов **совпадает**: каталог `<name>/SKILL.md`, YAML-frontmatter,
тело в Markdown.

| | claude-code | codex |
|---|---|---|
| файл | `<name>/SKILL.md` | `<name>/SKILL.md` |
| обязательные поля | нет обязательных, `description` — рекомендуемое | `name`, `description` |
| выбор скилла | по `description` | по `description` |
| явный вызов | `/<name>` | `$<name>` |
| каталог в проекте | `.claude/skills/<name>/` | `.agents/skills/<name>/` |

Отличается только **путь установки**, а не содержимое. Поэтому один файл на скилл.

Frontmatter сознательно ограничен двумя полями — `name` и `description`. Всё остальное,
что умеет claude-code (`allowed-tools`, `context: fork`, `model`, `effort`, `paths`, `hooks`,
инъекция вывода команд через `` !`cmd` ``), в codex не документировано. Любое такое поле
превращает общий файл в два разных. Ограничение — цена переносимости, и она здесь уместна:
вся логика живёт в `wk`, скиллу нужен только текст.

## Установка

`wk init` копирует каждый `<name>/SKILL.md` в оба каталога проекта:

```
.claude/skills/<name>/SKILL.md
.agents/skills/<name>/SKILL.md
```

Копии встроены в бинарь: сеть для `wk init --offline` не нужна.
Симлинки внутри проекта запрещены; симлинк над корнем проекта допускается.
Повторный `init` добавляет отсутствующие навыки. Существующие валидные файлы
сохраняются, различия выводятся как diff, даже при `--force`.

`wk init` и `wk doctor` проверяют frontmatter, имя каталога, описание, последний
шаг и запрещённые конструкции встроенным валидатором. Невалидный установленный
навык приводит к ошибке до записи при init и к `fail skills` в doctor.

`$<name>` и `/<name>` после этого доступны в обоих агентах.

## Состав

| скилл | когда | последний шаг |
|---|---|---|
| `policy-sync` | в начале задачи | `wk check --strict` |
| `doc-card` | нужного факта нет в `docs/` | `wk check --strict` |
| `implement-planned` | писать код по готовой документации | `wk check --strict` |
| `propose-rule` | пробел в политиках компании | `wk check --strict` |

`audit-docs` в первой версии отсутствует: сверка документации с политиками запускается из UI,
где есть человеческая сессия. `wikiagent` не принимает анонимные вызовы
(`backend/src/wikiagent/api.py:86-91`).

## Правила для новых скиллов

- `description` — одна строка, и в ней сказано, **когда вызывать и когда не вызывать**:
  codex требует именно этого, claude-code по этой же строке выбирает скилл;
- тело — нумерованные шаги в императиве. Без «почему», без примеров на три экрана;
- ни `curl`, ни URL вики, ни имени переменной с токеном. Вся работа с сетью и файлами — через `wk`;
- без слов «при необходимости», «желательно», «обычно». Только обязательные шаги;
- последний шаг — `wk check --strict`;
- правила из `docs-kit/AGENTS-snippet.md` не дублировать, а ссылаться на них;
- скилл не принимает предложения и не меняет статус факта в обход человека;
- скилла-оркестратора, запускающего остальные скиллы, нет.
